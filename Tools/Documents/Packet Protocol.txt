[HEADER]
The header is a 64 byte data chunk at the front of EVERY packet. Its structure is as follows (btw. INT = 4 bytes)

[INT HEAD]	-Variable always equal to 0x64616568 (which spells "head" in ascii)
[INT KEYOffset]	-Variable containing part of the key for the XORMask Cryptosystem.
[INT SysMessage]-ID declaring a system message to be sent. 0 = None, 2 = TCP Timeout (there are probably more. so find them)
[INT Sequence]	-This variable starts at 0 and gets incremented every packet. There is a seperate counter for the server and the client.
[INT XORSize]	-This is how much data after the header is RELEVANT to the packet. Since blowfish needs 8 byte blocks, garbage is appened to the end.
[INT BlfSize]	-This is how much data was went with the entire footer including the extra garbage to fit the blowfish block. its divisible by 8 always.
[INT Opcode?]	-This may very well be the opcode for each packet. Its different per packet type but is still a regular integer so its not trash.

[INT Footer]	-Variable is always equal to 0x6C696174 (which spells "foot" in ascii)


[Footer]
The Data after the header is the opcode specific data for each packet. When reversing you only need to do the XORSize number of bytes after the header.
Ignore the remaining bytes as they are filler used to meet blowfish block requirements.

BTW: The Data SEEMS to be in NetByte Order, or Big Endian. Google it if you dont know what it is...
ALSO: Variables of the packets will be labeled by standard JAVA sizes (BYTE = 1 BYTE, SHORT = 2 BYTE, INT = 4 BYTE, LONG = 8 BYTE, FLOAT = 4 BYTE)

[LOGINSERVER]
0x00030000 - Login Request
 - BYTE: UnicodeSize:  Size of Unicode String Following this Byte + 0x80. so 9 bytes is 0x89 
                       (This I think is to differentiate from Unicode and Ascii Strings in packets. If Size > 0x80 its unicode
 - UNICODE: USERNAME: String using 2 bytes per character (UTF-16LE) The "shorts" are in Little Endian or Host Byte Order
 - INT: ??? : 0X000010A9;
 - BYTE: PasswordSize: 0x80 This is how much of the remaining data is encrypted as the password. Take this Size /2 for the length of password.
 - ENCRYPTED: PASSWORD: The remaining bytes are the password, but its encrypted in blowfish.
Note: To Decrypt, create a new instance of the blowfish class and pass the Unicode version of the USERNAME and its Array Size
      As if it were binary data to teh constructor blowfish passcrypt = new Blowfish(UnicodeArray,Length); UnicodeArray = byte[] and Length = int
      Than just run a Decrypt() on the remaining bytes.
